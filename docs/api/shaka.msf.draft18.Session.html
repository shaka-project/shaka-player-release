readResponseTail_(payloadnon-null, offset, leadingVarInts, description) → {shaka.msf.draft18.Session.ResponseTail}

Finds the Track Properties at the end of a SUBSCRIBE_OK or FETCH_OK payload, and the LARGEST_OBJECT parameter on the way. The Track Properties run to the end of the message with no length of their own, so they start wherever the Parameters before them end. Parameters are the obstacle: since draft-18 a Parameter's value is encoded however its type says, rather than by the parity rule Properties use, so an unknown type cannot be stepped over. Only EXPIRES and LARGEST_OBJECT may appear in these two responses at all; the others the message layer knows are stepped over too so that a lenient publisher costs us nothing.

 Where delivery should begin, for a subscription that is not meant to start at the live edge, which is what a seek into published-but-not-yet-received content needs.
